# ブラウザで内容を更新する

## 方針

Pages CMSを編集画面として使い、既存のAstro・Markdown・GitHub Pagesを継続する。独自の管理画面やデータベースは作らない。`.pages.yml` に作品・活動、記事、自己紹介の編集項目を定義した。2026-11-05に本人の承認を受け、GitHub Appをこのポートフォリオ1件に限定して接続した。

Pages CMSは既存ファイルをフォームとリッチテキストエディターで編集でき、画像もリポジトリへアップロードできる。Keystaticも候補になるが、今回の静的サイトでは別の管理アプリや認証経路を増やさずに済むPages CMSから始める。

- [Pages CMSの仕組み](https://pagescms.org/docs/)
- [初期設定](https://pagescms.org/docs/quick-start/)
- [画像の保存先](https://pagescms.org/docs/configuration/media/)
- [本文の編集](https://pagescms.org/docs/configuration/fields/rich-text/)
- [比較したKeystaticのGitHubモード](https://keystatic.com/docs/github-mode)

## 初回だけ行うこと

1. この変更をリポジトリへ反映する。
2. [Pages CMS](https://app.pagescms.org/)にGitHubでログインする。
3. GitHub Appの対象を `Mori-kamiyama/Mori-kamiyama.github.io` に限定して接続する。外部サービスへの権限付与は本人の確認を経て行う。
4. リポジトリと編集するブランチを開く。ルートの `.pages.yml` が読み込まれる。
5. 下書きの本文変更、画像の選択・アップロード、保存後のビルドを一度確認する。

## 日々の更新

- 「作品・活動」からタイトル、説明、分野、画像、本文、ギャラリー、関連リンクを編集する。制作途中の試みや運営・調査も同じ形式で追加できる。
- 新規作品・記事の下書きスイッチはオンで始まる。本文や画像を確認したらオフにして保存する。掲載順は小さい番号ほど先になる。
- 「自己紹介」では紹介文、写真、キーワード、出身、経歴、ポリシー、価値観を編集する。紹介文と写真はHomeとProfileの両方に反映する。
- 本文は通常の編集画面で見出しや箇条書きを挿入できる。SourceモードでMarkdownを書く場合は `## 見出し` のように半角スペースを入れる。
- コードやHTMLの折りたたみを含む既存記事はSourceモードを使う。一般的なリッチテキスト編集によるHTMLの書き換えを避けるため。

`main` に保存した内容は既存のGitHub Actionsで検証され、合格すると公開される。保存から公開までビルドの待ち時間がある。検証に失敗した場合はGitHub Actionsのエラーを確認する。

画像は `src/assets/` に保存し、本文や表紙欄へ `../../assets/ファイル名` を書き込む。作品・記事・自己紹介のMarkdownを同じ深さに置くことで共通の画像設定を使う。Astroで画像を最適化する既存の流れを維持する。

## 下書きの扱い

`draft: true` の作品・記事は `npm run dev` で確認できる。作品カードと詳細に下書き表示を付ける。公開ビルドでは一覧、詳細、関連記事、RSS、SNS用画像、サイトマップから除外する。未設定の既存コンテンツは公開扱いを維持する。

下書きはサイトへの表示制御であり、リポジトリの閲覧権限は変えない。公開リポジトリに保存すればMarkdown自体は閲覧できるため、クライアントの内部資料や個人情報は入れない。

画像と制作年は任意。画像が未準備でもタイトルと本文から作品を追加でき、後から表紙を付けられる。制作年が不明な作品は年を表示しない。分野には研究、教材、映像、企画を追加し、作品一覧には実際に存在する分野のフィルターだけを表示する。

公開済みの作品・記事には `draft: false` を明示した。CMSで新規コンテンツ用の既定値が補われても、既存作品を誤って下書きに戻さないため。既存の投稿APIでも同じ `draft` フィールドを受け取れるようにした。

## 掲載内容

既存21件に7件を追加公開し、公開28件・下書き1件とした。掲載対象外とした紹介ファイルは現行版から削除。映像モンタージュは完成出力を確認できていないため下書きを維持する。確認できる制作内容を本文にし、成果の数値や受賞、実施・導入を推測で加えていない。給食パンフレットの説明も制作メモで補った。根拠は [掲載根拠](recent-work-sources.md) に記載。

共有されたFigma6件から、Idea Match、名刺、Sparklish、給食Webデザインを追加。ワークショップとTOROMINOは既存ページを補強した。名刺は連絡先を含まない面を使用。制作年を推測で追加せず、チーム作品の個人担当も資料で確認できる範囲だけ記載する。

## 検証

型チェック、公開ビルド、37 HTML・1253ローカルURLの検証、PC・スマホのPlaywright 36件、投稿API 10件が通過。残した下書きの公開ページ・一覧・サイトマップへの非掲載と、掲載対象外にしたページが生成されないことを確認した。開発画面では下書きの詳細と追加分野の絞り込み、スマホ幅の表示を確認した。`.pages.yml` はPages CMSの公式 `ConfigSchema` でも検証した。

Pages CMSで作品・活動の一覧、名刺の下書き編集、画像アップロード、文章と画像の保存を確認した。保存後にGitHubから取得し直し、本文、画像の相対パス、`draft: true`、省略した制作年が保たれることを確認した。同名画像を再アップロードすると連番付きのコピーになるため、既存画像の再利用にはSelectを使う。確認でできたコピーは元画像へ参照を戻して整理した。
