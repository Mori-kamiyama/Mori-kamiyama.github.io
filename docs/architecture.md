# ポートフォリオの設計と参照元

## 採用した構成

Astro 7 / TypeScript / CSS / Markdown。静的HTMLを生成し、GitHub ActionsからGitHub Pagesへ公開する。メニューと作品の絞り込みにのみJavaScriptを使う。ReactやCMSは現時点では必要ない。

HugoもMarkdown、分類、画像処理、単一実行ファイルを備え、この用途に十分対応できる。今回は独自のFigmaデザインに沿ったUIをHTMLに近いコンポーネントで組み、TypeScriptの操作コードと同じ環境で管理するためAstroを選んだ。ビルド速度が選定理由ではない。今後の記事数が増えても静的生成を継続する想定。

- Hugo: https://gohugo.io/about/features/
- Astro: https://docs.astro.build/en/concepts/islands/

作品説明は原文の事実を保って整理した。短い原文しかない作品では、担当工程・定量成果・実装詳細を推測して追加していない。カテゴリーは原文をもとに実装上分類したもの。ブログのAI記事は公開されている本文のみ移し、続きを創作していない。公開日がないため日付なしとして扱う。ポートフォリオ記事の公開日は元サイトの2025-12-18、作品カードの年度は公開サイトの2026を維持している。

## デザイン

元デザインの白黒、Figtreeの英字、写真、細い罫線、商品棚のような作品グリッドを軸とする。日本語の元デザインには商用フォントが使われていたため、それを無断で配布せずNoto Sans JPを採用。フォントはサイト内で配信する。

Homeは作品画像を白黒で表示し、ホバーやキーボードフォーカスで元の色を見せる。Works一覧は元のカラー画像を使う。本文と詳細リンクを読めるサイズにし、Homeの作品抜粋には下端の白いフェードを付ける。全作品へのリンクはフェードの外に置き、キーボードで作品にフォーカスすると抜粋を展開する。Skillsは2段を逆方向に流し、両端を白くフェードさせる。停止・再開と、動きを減らすOS設定での静的表示に対応する。おすすめ記事は本文冒頭を3行分の高さでフェードし、タイトルと全文へのリンクは省略しない。スマホでは写真と本文が重ならない順序に並べる。

基本色: 白 `#ffffff`、本文・罫線 `#1e1e1e`、補助文字 `#686868`、薄い罫線 `#dedede`、画像下地 `#f5f5f5`。

## 内容と画像

`src/content.config.ts` のスキーマで作品・記事を検証する。画像参照、カテゴリー、年度などが不正ならビルドを失敗させる。一覧と詳細は同じ作品データから生成する。

Figmaの一時URLやStudioへの実行時画像依存を残さず、元素材を `src/assets/` に保存した。Astroで表示用WebPとレスポンシブ画像を生成する。FaviconとOG画像は元の公開サイトのブランド素材を使用する。

## 問い合わせと公開

問い合わせは元サイトに公開済みのXへの導線と、GitHub・Zennへのリンク。利用者が送信できたと誤認するフォームを置かない。公開サイトのLinkedInリンクは相対URLになっており、リンク先を確実に特定できなかったため移植していない。アカウント情報から非公開のメールアドレスを掲載していない。

フォームが必要になった場合は受信先と外部サービスを確認してから追加する。GitHub Pagesのみではサーバー側のメール送信は行えない。

Pagesはユーザーサイトのため `/` を基準にし、リポジトリ名をbaseパスとして付けない。元サイトの `/1` に相当するローカルパスはPortfolio詳細へ移動する。404ページ、各ページのcanonical・説明・OG、サイトマップ、robots.txt、日付付き記事のRSSを用意した。

## 検証方針

型チェック、静的ビルド、生成されたローカルリンクとアンカー、全コンテンツページのHTTP応答・画像・メタデータを確認する。PlaywrightでPCとスマホの操作を検証し、320 / 375 / 412 / 768 / 1024 / 1512pxの主要ページの横はみ出しを確認する。axeで主要ページのWCAG A/AAを機械検査する。機械検査だけで完全なアクセシビリティを保証するものではなく、画面の目視確認も行う。
